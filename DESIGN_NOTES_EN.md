# Implementation and Derivation Notes

## 1. Rigid-Body Model

The state is `x = [p; v; q; w]`. Position `p` and velocity `v` are expressed in NED, angular velocity `w` is expressed in FRD, and `q` represents rotation from FRD to NED. `R(q)` is the corresponding rotation matrix.

```text
p_dot = v
v_dot = [0,0,g]' - R(q) * [0,0,sum(T)]' / m
q_dot = 0.5 * q (Hamilton product) [0,w]'
w_dot = inv(J) * (tau - cross(w,J*w))
```

The rotor mixing relationship is:

```text
[total_thrust; tau_x; tau_y; tau_z] = mix * [T0; T1; T2; T3]
```

The roll torque row is `dy*[-1,-1,1,1]`, the pitch torque row is `dx*[-1,1,1,-1]`, and the yaw torque row is `c_tau*[-1,1,-1,1]`. Each rotor produces `T = mg/4 = 2.943 N` in hover.

The self-tests verify zero-thrust free fall, hover equilibrium, and the torque directions produced by differential thrust. The model excludes aerodynamic drag, motor lag, and wind. These effects are not defined by the assignment's nominal parameters and require additional calibration or modeling if introduced in Gazebo.

## 2. Reference States

Position, velocity, and acceleration are computed from the assignment's analytical trajectory equations. The yaw reference is `psi = atan2(v_E, v_N)`. To produce an attitude reference consistent with the acceleration required for turning:

```text
b3 = normalize([0,0,g]' - a_ref)
heading = [cos(psi), sin(psi), 0]'
b2 = normalize(cross(b3, heading))
b1 = cross(b2, b3)
R_ref = [b1,b2,b3]
```

The angular-velocity reference is obtained from the skew-symmetric part of `R_ref' * Rdot_ref`. `Rdot_ref` is approximated using a small central time difference. Translational velocity and acceleration continue to use analytical derivatives. The attitude reference is used for initialization and in the cost function; actual motion is generated by the dynamics.

## 3. EKF

The filter uses a right-multiplicative attitude error:

```text
q_true = q_hat * Exp(dtheta)
nominal_state = [p; v; q; ba; bg]
error_state = [dp; dv; dtheta; dba; dbg]

a_corrected = a_measurement - ba_hat
w_corrected = w_measurement - bg_hat
a_world = R(q_hat)*a_corrected + gravity
```

Propagation uses the half-step attitude to transform specific force, second-order position integration, and a quaternion exponential update. The nonzero blocks of the linearized continuous-time error dynamics are:

```text
F_pv = I
F_vtheta = -R*skew(a_corrected)
F_vba = -R
F_thetatheta = -skew(w_corrected)
F_thetabg = -I
```

The state-transition approximation is `Phi = I + F*dt + (F*dt)^2/2`. Sample noise contributes velocity and attitude increments scaled by `sigma_a*dt` and `sigma_w*dt`, respectively. Bias random walks scale as `density*sqrt(dt)`. These quantities must not be treated as interchangeable continuous-time noise parameters.

For the position update, `H = [I,0]`, `R_pos = sigma_p^2*I`, and `K = P*H'/(H*P*H' + R_pos)`. The covariance is updated using the Joseph form. The local attitude correction is then injected into the quaternion, and the attitude-error covariance is reset using the block `I - skew(dtheta)/2`. Covariance matrices are symmetrized after updates, and the tests inspect their minimum eigenvalues.

Estimation-error plots use truth minus the nominal estimate. Attitude error is defined as `Log(q_hat^-1*q_true)`. Since `q` and `-q` represent the same attitude, direct quaternion subtraction is not used as the attitude-error definition.

The ±2σ coverage values are descriptive statistics from individual trajectories, not a calibration guarantee established through repeated Monte Carlo trials. Bias and heading observability depend on motion excitation and the initial prior.

## 4. NMPC Numerical Formulation

The default configuration uses `N = 20`, `Ts = 0.05 s`, and six move blocks with lengths `[1,1,2,3,5,8]`. Each block has four independent variables. An invertible linear transformation maps the optimization variables to four rotor thrusts to improve numerical conditioning:

```text
M = mix \ diag([mass; Jxx; Jyy; Jzz])
T = T_hover + M*z
```

This is an input reparameterization. The physical thrust vector `T` still drives the full nonlinear quadrotor model. Physical thrust limits enter `fmincon` as linear inequalities in `z`; post-optimization clipping is not used to hide constraint violations.

The stage cost includes weighted squared position and velocity errors, the sign-invariant attitude error `1-(q'*q_ref)^2`, angular-velocity error, deviations from hover thrust, and changes in thrust. Terminal state-error costs are multiplied by four. The cost sum is weighted by `Ts`; individual weights are defined in the configuration file.

Constraints are applied at the end of every RK4 substep. Quaternions are normalized after each substep, so a redundant unit-norm equality constraint is not added. Attitude constraints are expressed using rotation-matrix entries:

```text
 R32 - tan(limit)*R33 <= 0
-R32 - tan(limit)*R33 <= 0
 R31 - sin(limit) <= 0
-R31 - sin(limit) <= 0
```

Together, the first two inequalities enforce nonnegative `R33` and bound roll. Combined with the pitch bounds, they are equivalent to separate roll and pitch limits on the normal attitude branch. Body rates are normalized axis by axis to the range `[-1,1]`.

Complex-step objective and constraint gradients are computed using a batch of trajectories with imaginary perturbations. The prediction code uses `sqrt(sum(q.^2))` rather than a conjugate-based norm, preserving the analytical extension required by the complex-step method. The cost also uses nonconjugate sums of squares. The real objective is supplied to `fmincon`; imaginary components are used only for derivatives. `run_tests` checks these gradients against independent central finite differences.

The previous input sequence is shifted forward, then sampled at the move-block starting points to initialize the next solve. Move blocking reduces the number of decision variables but also restricts control freedom. Increasing the number of blocks can improve flexibility at greater computational cost.

## 5. Analysis and Limitations

Thrust constraints are enforced by the optimization problem. Actual state constraints must still be checked against recorded simulation samples. Checks at integration nodes do not establish a mathematical guarantee of continuous-time constraint satisfaction. Ground truth is recorded at 100 Hz, while internal physics integration runs at 500 Hz. A more detailed investigation of between-sample violations would require recording all physics substeps.

Reported solve time covers one optimization call and its objective/gradient evaluations. It excludes plotting and file export and does not represent the complete online communication cycle. Total wall-clock simulation time is reported separately. Online ROS execution must leave room for communication overhead; completing an offline simulation does not demonstrate real-time capability.

Trajectory derivatives, NED signs, torque mixing, quaternion conventions, EKF covariance reset, and physical units are key topics the group should be able to explain during the presentation.
